Section 1 — What Is a Heap?

A heap is a complete binary tree stored as a flat array satisfying the heap property: every parent is >= its children (max-heap) or <= its children (min-heap). This guarantees O(1) access to the extreme element and O(log n) insert / delete.

Real-World Analogy: Hospital Emergency Room
	•	Patients arrive with different severity levels — the most critical patient is always treated next.
	•	A new critical patient jumps ahead of less-critical ones already waiting.
	•	Each arrival (push) and each treatment (pop) costs O(log n) to maintain order.
	•	This is exactly a max-heap (priority queue): the highest-priority element always lives at the root.

1.1 — Heap Stored as an Array
Heap: Tree-to-Array Mapping
  Max-Heap tree:           Stored as array (0-indexed):

         10                Index: [ 0] [ 1] [ 2] [ 3] [ 4] [ 5] [ 6]
        /  \               Value: [10] [ 9] [ 8] [ 7] [ 6] [ 5] [ 4]
       9    8
      / \  / \
     7   6 5   4

  Index arithmetic (0-indexed):
    Parent of node i    : (i - 1) / 2
    Left child of node i:  2*i + 1
    Right child of node i: 2*i + 2

  Verify node at index 1 (value = 9):
    Parent      = (1-1)/2 = 0  ->  value 10   OK (10 >= 9)
    Left child  =  2*1+1  = 3  ->  value  7   OK (9 >= 7)
    Right child =  2*1+2  = 4  ->  value  6   OK (9 >= 6)

  'Complete binary tree' = nodes filled left-to-right at every level
  => array is always contiguous, zero wasted slots, no pointers needed.

         11          <-- 11 is now root, heap property satisfied everywhere
        /  \

         4           <-- 4 is now at root, heap property violated
        / \
       9   8

Diagram 3 — Top-K Pattern with a Min-Heap
Top-K Pattern: Min-Heap of Size K
  Problem: Find top-3 largest from stream [5, 2, 9, 1, 7, 3, 6]
  Strategy: maintain a MIN-HEAP of size k=3.
  The heap always holds the k largest elements seen so far.
  The ROOT = smallest of the top-k = the kth largest element.

  num=5:  size < 3 -> push.              heap = [5]
  num=2:  size < 3 -> push.              heap = [2, 5]
  num=9:  size < 3 -> push.              heap = [2, 5, 9]
  num=1:  1 <= root(2) -> discard.       heap = [2, 5, 9]
  num=7:  7 >  root(2) -> push, pop 2.   heap = [5, 7, 9]
  num=3:  3 <= root(5) -> discard.       heap = [5, 7, 9]
  num=6:  6 >  root(5) -> push, pop 5.   heap = [6, 7, 9]

  Final: heap = {6, 7, 9}  =  top-3 largest.  Correct!
  heap.top() = 6  =  3rd largest element.

  Intuition: the root is the 'weakest' member of the current top-k club.
  Any new element that beats the root earns a spot; the root is evicted.


Diagram 4 — Two-Heap Median
Two-Heap Median: Invariants and Insert Trace
  Stream so far: [1, 2, 3, 4, 5]

  lower (max-heap) = [1, 2, 3]   <-- lower half, root = 3 (largest of lower)
  upper (min-heap) = [4, 5]       <-- upper half, root = 4 (smallest of upper)

  Invariant 1: lower.top() <= upper.top()  (3 <= 4  OK)
  Invariant 2: |lower.size() - upper.size()| <= 1

  findMedian(): lower.size() > upper.size()  ->  return lower.top() = 3.
  (Odd total: median is the middle element = 3.  Correct.)

  Insert 6:
    Push 6 to lower -> lower = [1,2,3,6]
    6 > upper.top()=4 -> move 6 to upper: upper = [4,5,6]
    lower.size()=3, upper.size()=3  ->  balanced.
    findMedian() = (lower.top() + upper.top()) / 2 = (3+4)/2 = 3.5.  Correct.

4.1 — C++ priority_queue: Complete API
// C++ priority_queue — Complete API
#include <queue>
#include <vector>
#include <functional>
using namespace std;

// ── MAX-HEAP (default) ───────────────────────────────────────
priority_queue<int> maxH;
maxH.push(5);           // insert:        O(log n)
maxH.top();             // peek max:       O(1)  -- does NOT remove
maxH.pop();             // remove max:     O(log n)  -- returns void!
maxH.size();            // element count:  O(1)
maxH.empty();           // true if empty:  O(1)

// ── MIN-HEAP ─────────────────────────────────────────────────
priority_queue<int, vector<int>, greater<int>> minH;
minH.push(5);
minH.top();             // peek minimum
minH.pop();             // remove minimum

// ── MIN-HEAP OF PAIRS (for Dijkstra) ────────────────────────
using P = pair<int,int>;
priority_queue<P, vector<P>, greater<P>> pq;
pq.push({dist, node});  // ordered by dist ascending

// ── BUILD HEAP FROM VECTOR — O(n) ────────────────────────────
vector<int> v = {3,1,4,1,5,9,2,6};
priority_queue<int> h(v.begin(), v.end());  // O(n), not O(n log n)

// ── CUSTOM COMPARATOR ────────────────────────────────────────

4.2 — Manual Min-Heap (Understanding Internals)
// Manual Min-Heap — Internals
// Implementing a min-heap from scratch to understand sift-up / sift-down
class MinHeap {
    vector<int> h;

    void siftUp(int i) {
        while (i > 0) {
            int p = (i - 1) / 2;
            if (h[p] > h[i]) { swap(h[p], h[i]); i = p; }
            else break;
        }
    }

    void siftDown(int i) {
        int n = h.size();
        while (true) {
            int sm = i, l = 2*i+1, r = 2*i+2;
            if (l < n && h[l] < h[sm]) sm = l;
            if (r < n && h[r] < h[sm]) sm = r;
            if (sm == i) break;
            swap(h[i], h[sm]);
            i = sm;
        }
    }

public:
    void push(int v) { h.push_back(v); siftUp((int)h.size()-1); }
    int  top()       { return h[0]; }
    void pop()       { h[0]=h.back(); h.pop_back(); if (!h.empty()) siftDown(0); }
    int  size()      { return (int)h.size(); }
    bool empty()     { return h.empty(); }
};


4.3 — Heap Sort: O(n log n) O(1) Space
Phase 1: build a max-heap in O(n) by sifting down from the last non-leaf. Phase 2: repeatedly swap the root (max) with the last element, shrink the heap boundary, sift down.

// Heap Sort — O(n log n) O(1) extra space
void siftDown(vector<int>& a, int i, int n) {
    while (true) {
        int lg = i, l = 2*i+1, r = 2*i+2;
        if (l < n && a[l] > a[lg]) lg = l;
        if (r < n && a[r] > a[lg]) lg = r;
        if (lg == i) break;
        swap(a[i], a[lg]); i = lg;
    }
}

void heapSort(vector<int>& a) {
    int n = a.size();
    // Phase 1: build max-heap — O(n)
    for (int i = n/2-1; i >= 0; i--) siftDown(a, i, n);
    // Phase 2: extract max one by one — O(n log n)
    for (int end = n-1; end > 0; end--) {
        swap(a[0], a[end]);       // move max to sorted tail
        siftDown(a, 0, end);      // restore heap on unsorted prefix
    }
}
// Not stable. Use merge sort if element order must be preserved.


4.4 — Two-Heap Pattern: Median of Data Stream
Keep a max-heap for the lower half and a min-heap for the upper half. After every insert, enforce two invariants: lower.top() <= upper.top(), and sizes differ by at most 1.

// Median from Data Stream — Two Heaps
// LeetCode 295 — Find Median from Data Stream
// addNum: O(log n)   findMedian: O(1)
class MedianFinder {
    priority_queue<int> lo;                          // max-heap: lower half
    priority_queue<int,vector<int>,greater<int>> hi; // min-heap: upper half
public:
    void addNum(int num) {
        lo.push(num);                   // always push to lower first
        // Invariant 1: lo.top must not exceed hi.top
        if (!hi.empty() && lo.top() > hi.top()) {
            hi.push(lo.top()); lo.pop();
        }
        // Invariant 2: sizes differ by at most 1
        if (lo.size() > hi.size() + 1) {
            hi.push(lo.top()); lo.pop();
        } else if (hi.size() > lo.size()) {
            lo.push(hi.top()); hi.pop();
        }
    }
    double findMedian() {
        if (lo.size() > hi.size()) return lo.top();
        return (lo.top() + hi.top()) / 2.0;
    }
};

The Heap Decision Flowchart
	•	Need the MINIMUM repeatedly?         -> Min-heap  (greater<> comparator).
	•	Need the MAXIMUM repeatedly?         -> Max-heap  (default priority_queue).
	•	Top-K LARGEST from n elements?       -> MIN-heap size K. Root = kth largest. Evict if new > root.
	•	Top-K SMALLEST from n elements?      -> MAX-heap size K. Root = kth smallest. Evict if new < root.
	•	Running MEDIAN from a stream?        -> Two heaps: max-heap (lower) + min-heap (upper).
	•	Merge K sorted sequences?            -> Min-heap size K storing (value, list_idx, elem_idx).
	•	Shortest path on weighted graph?     -> Min-heap (dist, node) = Dijkstra.
	•	Counter-intuitive rule: use a MIN-heap to track the top-K LARGEST. The min-heap root is the weakest member of the top-K club and the first to be evicted when a stronger candidate arrives.

6.1 — K Closest Points to Origin
// K Closest Points — O(n log k)
// LeetCode 973 — K Closest Points to Origin
// Time: O(n log k)   Space: O(k)
vector<vector<int>> kClosest(vector<vector<int>>& pts, int k) {
    // Max-heap on squared distance; root = farthest of current k closest
    priority_queue<pair<int,int>> maxH;  // {dist^2, index}
    for (int i = 0; i < (int)pts.size(); i++) {
        int d = pts[i][0]*pts[i][0] + pts[i][1]*pts[i][1];
        maxH.push({d, i});
        if ((int)maxH.size() > k) maxH.pop();  // evict farthest
    }
    vector<vector<int>> res;
    while (!maxH.empty()) {
        res.push_back(pts[maxH.top().second]);
        maxH.pop();
    }
    return res;
}


6.2 — Dijkstra's Shortest Path
// Dijkstra — O((V+E) log V)
// Dijkstra using min-heap of (distance, node)
// Time: O((V+E) log V)   Space: O(V+E)
vector<int> dijkstra(int src, int V,
                     vector<vector<pair<int,int>>>& adj) { // adj[u]={(w,v)}
    vector<int> dist(V, INT_MAX);
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
    dist[src] = 0;
    pq.push({0, src});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;     // stale entry — skip
        for (auto [w, v] : adj[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});
            }
        }
    }
    return dist;   // dist[i] = shortest distance from src to i
}


6.3 — Top K Frequent Elements
// Top K Frequent Elements — O(n log k)
// LeetCode 347 — Top K Frequent Elements
// Time: O(n log k)   Space: O(n)
vector<int> topKFrequent(vector<int>& nums, int k) {
    // Step 1: count frequencies
    unordered_map<int,int> freq;
    for (int x : nums) freq[x]++;

    // Step 2: min-heap on frequency, size capped at k
    //  root = least-frequent of the current top-k (candidate to evict)
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> minH;
    for (auto& [val, cnt] : freq) {
        minH.push({cnt, val});
        if ((int)minH.size() > k) minH.pop();
    }

    // Step 3: extract results
    vector<int> res;
    while (!minH.empty()) { res.push_back(minH.top().second); minH.pop(); }
    return res;
}
// Bucket-sort alternative achieves O(n) time when value range is small.

Why Build-Heap is O(n) not O(n log n)
	•	Inserting n elements one-by-one: each push is O(log n) => O(n log n) total.
	•	Heapify (build from array): sift-down every node starting from the last non-leaf.
	•	Nodes at height h: at most ceil(n / 2^(h+1)) nodes, each costs O(h) to sift down.
	•	Total work = sum over h of  n/2^h * h  =  O(n)  by the geometric-series identity.
	•	Practical: priority_queue<int>(v.begin(), v.end()) is O(n). Prefer it over n pushes.

Section 8 — Solved Problem 1
Solved Problem 1
Kth Largest Element in an Array
View on LeetCode ->
Medium

OBSERVATIONS  

Return the kth largest element in sorted order (not kth distinct). Constraints: 1 <= k <= n <= 10^5.

	•	Brute force: sort descending, return index k-1. O(n log n) — correct but not optimal.
	•	Heap insight: A min-heap of exactly k elements always holds the k largest seen so far. Its root = kth largest. Time: O(n log k).
	•	QuickSelect insight: Partition-based selection (like QuickSort but recurse on one side only). Average O(n), O(1) space — optimal for this problem in an interview.
	•	Heap approach is better when k << n (e.g. k=10, n=10^6) because O(n log k) << O(n log n).

BRUTE FORCE  Sort — O(n log n) O(1)

// Brute Force — Sort
int findKthLargestSort(vector<int>& nums, int k) {
    sort(nums.begin(), nums.end(), greater<int>());
    return nums[k-1];
}
// Correct. Interviewer will then ask: 'Can you do better?'


OPTIMISED SOLUTION  Min-Heap of Size K — O(n log k) O(k)

// Kth Largest — Min-Heap Size K — O(n log k)
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        // Min-heap: root = smallest of the k largest seen so far
        priority_queue<int, vector<int>, greater<int>> minH;

        for (int num : nums) {
            minH.push(num);
            if ((int)minH.size() > k)
                minH.pop();   // evict the smallest — it can't be in top-k
        }
        // Root = kth largest overall
        return minH.top();
    }
};

BONUS — QuickSelect  O(n) average  O(n^2) worst  O(1) space

// QuickSelect — O(n) average
// Hoare-style partition (descending order for kth largest)
int partition(vector<int>& a, int lo, int hi) {
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++)
        if (a[j] >= pivot) swap(a[i++], a[j]);
    swap(a[i], a[hi]);
    return i;   // pivot is now at its final sorted position
}

int qs(vector<int>& a, int lo, int hi, int k) {
    if (lo == hi) return a[lo];
    int p = partition(a, lo, hi);
    if      (p == k-1) return a[p];          // found it
    else if (p <  k-1) return qs(a, p+1, hi, k);  // kth is right of p
    else               return qs(a, lo, p-1, k);  // kth is left of p
}

int findKthLargest(vector<int>& nums, int k) {
    return qs(nums, 0, (int)nums.size()-1, k);
}
// Randomise pivot for worst-case safety: swap(a[lo+rand()%(hi-lo+1)], a[hi]);

Section 9 — Solved Problem 2
Solved Problem 2
Merge K Sorted Lists
View on LeetCode ->
Hard

OBSERVATIONS  

Given k sorted linked lists, merge them into one sorted linked list and return its head.

	•	Brute: collect all n values, sort, rebuild. O(n log n) time, O(n) space — works but wastes the sorted structure.
	•	Pairwise merge: merge two lists at a time, k-1 rounds. Total O(kn) — slow when k is large.
	•	Heap insight: A min-heap of k entries (one per list head) always gives the global minimum in O(log k). After extracting a node, push its successor from the same list. O(n log k) total.
	•	Each of the n nodes is pushed once and popped once => 2n heap operations, each O(log k) => O(n log k).

BRUTE FORCE  Collect + Sort — O(n log n) O(n)

// Brute Force — O(n log n)
ListNode* mergeKListsBrute(vector<ListNode*>& lists) {
    vector<int> vals;
    for (ListNode* h : lists)
        for (ListNode* c = h; c; c = c->next) vals.push_back(c->val);
    sort(vals.begin(), vals.end());
    ListNode dummy(0); ListNode* cur = &dummy;
    for (int v : vals) { cur->next = new ListNode(v); cur = cur->next; }
    return dummy.next;
}


OPTIMISED SOLUTION  Min-Heap of K Heads — O(n log k) O(k)

// Merge K Sorted Lists — Min-Heap — O(n log k)
struct ListNode { int val; ListNode* next;
    ListNode(int x) : val(x), next(nullptr) {} };

class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        // comparator: min-heap ordered by node value
        auto cmp = [](ListNode* a, ListNode* b){ return a->val > b->val; };
        priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> minH(cmp);

        // Seed heap with head of each non-empty list
        for (ListNode* h : lists) if (h) minH.push(h);

        ListNode dummy(0);
        ListNode* tail = &dummy;

        while (!minH.empty()) {
            ListNode* node = minH.top(); minH.pop();
            tail->next = node;          // attach global minimum
            tail = tail->next;
            if (node->next) minH.push(node->next); // advance that list
        }
        return dummy.next;
    }
};

Section 10 — Common Mistakes & Edge Cases

10.1 — Heap Usage Mistakes

	•	MISTAKE: Using default max-heap when a min-heap is needed. For top-K LARGEST, you need a MIN-heap of size K. Using a max-heap gives the wrong eviction direction.
	•	MISTAKE: Calling pq.top() or pq.pop() on an empty heap. Always check pq.empty() first — accessing an empty priority_queue is undefined behaviour.
	•	MISTAKE: pop() returns void. You must read pq.top() first, then call pq.pop() separately.
	•	MISTAKE: Two-heap median — skipping the rebalancing step after each addNum. Both invariants (value ordering and size balance) must be enforced every time.
	•	MISTAKE: Merge K lists — pushing nullptr when a list is exhausted. Always guard: if (node->next) minH.push(node->next).
	•	MISTAKE: Using a heap when nth_element() suffices. For a static array, std::nth_element gives O(n) with simpler code.

10.2 — Conceptual Mistakes

	•	MISTAKE: Confusing kth largest with kth smallest. Always verify with a two-element example before coding.
	•	MISTAKE: Building a max-heap of all n elements then popping k times — O(n + k log n). Correct but slower than a min-heap of size k when k << n.
	•	MISTAKE: Expecting heap sort to be stable. It is NOT. Equal elements may reorder. Use merge sort when stability is required.
	•	MISTAKE: Expecting O(1) search in a heap. Only the top element is O(1). Finding any other element is O(n). Use a hash map alongside the heap when you need fast arbitrary lookup.
	•	MISTAKE: Forgetting the 'if (d > dist[u]) continue' guard in Dijkstra. Without it, stale heap entries cause incorrect distance relaxations.

10.3 — Edge Cases to Always Test

	•	k = 1: kth largest = maximum. An O(n) max scan suffices; heap is overkill.
	•	k = n: kth largest = minimum. Same — an O(n) min scan suffices.
	•	All elements equal: heap comparisons remain consistent; all operations correct.
	•	Negative numbers: STL comparators handle negatives correctly.
	•	Empty list heads in Merge K Lists: skip null pointers during heap initialisation.
	•	k = 0 lists: return nullptr immediately for Merge K Lists.
	•	Dijkstra with large weights: use long long for distances to avoid INT_MAX + w overflow.
	•	Single-element stream: two-heap median — lower has 1 element, upper has 0; findMedian returns lower.top().

Chapter 6 — Key Takeaways
	•	Heap = complete binary tree as array. Parent: (i-1)/2. Left child: 2i+1. Right child: 2i+2.
	•	Min-heap: root is minimum. Max-heap: root is maximum. O(1) peek, O(log n) push/pop.
	•	Build from array in O(n): use priority_queue(v.begin(), v.end()), not n individual pushes.
	•	Top-K LARGEST: min-heap size K. Root = kth largest. Evict root when new element > root.
	•	Top-K SMALLEST: max-heap size K. Root = kth smallest. Evict root when new element < root.
	•	Running median: max-heap (lower half) + min-heap (upper half). Keep sizes balanced, tops ordered.
	•	Merge K sorted lists/arrays: min-heap of K heads. O(n log k). Each node pushed/popped exactly once.
	•	Dijkstra: min-heap of (dist, node). Skip stale entries with 'if (d > dist[u]) continue'.
	•	C++ min-heap: priority_queue<int, vector<int>, greater<int>>. Never forget the third template argument.
