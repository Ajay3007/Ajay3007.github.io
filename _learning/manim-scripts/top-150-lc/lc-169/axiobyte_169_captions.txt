Majority Element — LeetCode 169 — found in O(1) space, no hash map 👇

The majority element appears more than half the time. The obvious move is a hash map that counts everyone — but that's O(n) space. There's something better: Boyer-Moore Voting. 🧠

Hold one candidate and a count. Walk the array:
• same as candidate → count + 1
• different → count − 1
• count hits 0 → the next element becomes the new candidate

Think of it as opposing votes cancelling out. Since the majority appears more than half the time, it can never be fully cancelled — so whoever is left standing at the end is the answer.

→ O(n) time, O(1) space ✅

Majority Element (LeetCode 169) solved in O(1) space with the Boyer-Moore Voting Algorithm — no hash map needed.

The majority element appears more than n/2 times. Counting with a hash map works but uses O(n) space. Boyer-Moore does it in O(1): keep a single candidate and a count. As you scan, add 1 when the current value matches the candidate and subtract 1 when it doesn't; whenever the count hits 0, the next value becomes the new candidate. It is like opposing votes cancelling out — and because the majority element appears more than half the time, it can never be fully cancelled, so it is the value left as the candidate at the end.

⏱️ O(n) time · O(1) space
