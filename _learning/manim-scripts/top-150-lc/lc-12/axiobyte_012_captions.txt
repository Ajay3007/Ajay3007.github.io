-- Caption --
Integer to Roman — LeetCode 12 — it's just making change 👇

You've got 13 "coins": the seven symbols (I, V, X, L, C, D, M) plus the six subtractive pairs (IV, IX, XL, XC, CD, CM). Turning a number into Roman is exactly the cashier's move — pay with the biggest coin that fits, over and over. 🪙

Sort the 13 values biggest → smallest. Then for each value: WHILE num ≥ value, append its symbol and subtract it. The "while" (not "if") is what lets a coin repeat.

2024 →
• 2024 ≥ 1000 → M (num 1024) → 1024 ≥ 1000 → M again (num 24)  ← the double M
• 24 ≥ 10 → X (num 14) → 14 ≥ 10 → X again (num 4)
• 4 ≥ 4 → IV (num 0)
= MMXXIV ✅

Pro move: skip the loop entirely and index each decimal digit straight into a lookup table (thousands/hundreds/tens/ones) — pure O(1).

→ O(1) time, O(1) space (the table is a fixed 13 rows)

-- Title --
Integer to Roman — LeetCode 12 (Greedy + the O(1) Lookup Trick)

-- Description --
Integer to Roman (LeetCode 12), built as a making-change problem, plus the elegant digit-lookup version.

There are 13 building blocks: the seven Roman symbols (I=1, V=5, X=10, L=50, C=100, D=500, M=1000) and the six subtractive pairs (IV=4, IX=9, XL=40, XC=90, CD=400, CM=900). Converting a number is exactly like paying with coins: line the 13 values up from largest to smallest, then repeatedly take the biggest value that still fits, append its symbol, and subtract it from the number.

The greedy loop: for each (value, symbol) in the sorted table, WHILE num ≥ value, append symbol and do num -= value. Using while rather than if is what allows a symbol to repeat, e.g. MM or XXX.

Worked example, 2024: take M (→1024), take M again (→24), then X (→14), X again (→4), then the subtractive pair IV (→0). The result is MMXXIV.

Elegant alternative (shown as a flourish): because a number 1–3999 has at most four decimal digits, you can precompute four small lookup arrays — thousands, hundreds, tens, ones — and just concatenate th[n/1000] + hu[n/100%10] + te[n/10%10] + on[n%10]. No loop at all.

⏱️ O(1) time · O(1) space — the value table is a fixed size, so the work doesn't grow with the input.
