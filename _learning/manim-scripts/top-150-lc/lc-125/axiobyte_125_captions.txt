Valid Palindrome — LeetCode 125 — the two-pointer starter 👇

Is the string a palindrome if you keep only letters/digits and ignore case? "A man, a plan, a canal: Panama" → true. "race a car" → false.

The move: one pointer at each end, walking inward. 👉👈
• skip anything that isn't a letter or digit
• compare the two characters, lowercased
• mismatch → false, immediately
• pointers meet in the middle → true

"race a car": r=r ✓, a=a ✓, c=c ✓ … then the right pointer hops over a space and lands on 'a', so we compare 'e' vs 'a' → they differ → false. No need to check the rest.

→ O(n) time, O(1) space — nothing allocated, you just walk the ends toward the center.

Bonus (cleaner code): strip to alphanumeric-lowercase, then compare the string to its reverse — shorter, but O(n) space.

-- Title --
Valid Palindrome — LeetCode 125 (Two Pointers, O(1) Space)

-- Description --
Valid Palindrome (LeetCode 125) — the classic two-pointer warm-up, and the first episode of the Two Pointers section.

Decide whether a string is a palindrome when you consider only alphanumeric characters and ignore letter case. Rather than build a cleaned-up copy, walk the original string from both ends: put one pointer l at the start and another r at the end. Skip any character that isn't a letter or digit, compare the lowercased characters at l and r, and if they ever differ the answer is false. If the pointers cross, every pair matched and it's a palindrome.

Example "race a car": r/r, a/a, c/c all match and the pointers step inward. Then the right pointer is on a space, which isn't alphanumeric, so it moves left onto 'a'. Comparing 'e' with 'a' fails — the string is not a palindrome, and we stop immediately without scanning the rest.

⏱️ O(n) time, O(1) extra space — the two-pointer walk allocates nothing.

Bonus, cleaner code (shown as a flourish): build a filtered string of just the lowercase alphanumeric characters, then check it equals its own reverse — more concise, at the cost of O(n) space.
