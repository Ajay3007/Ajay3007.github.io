-- Caption --
Zigzag Conversion — LeetCode 6 — stop overthinking the geometry 👇

Write the string in a zigzag over N rows, then read it back row by row. The naive instinct is to compute (row, col) coordinates for every character. Don't. 🧠

Keep ONE text bucket per row. Walk the string once, dropping each char into the current row, and bounce the direction: go down until the bottom row, flip, go up until the top row, flip again. Then concatenate the rows top to bottom.

"PAYPALISHIRING" over 3 rows:
row 0 → PAHN
row 1 → APLSIIG
row 2 → YIR
answer → "PAHNAPLSIIGYIR" ✅

The bounce is the whole trick: cur += down, and down flips sign whenever cur hits row 0 or the last row.

→ O(n) time, O(n) space for the buckets (O(1) extra if you skip the buffers and jump directly to each row's indices with a fixed 2·numRows−2 stride).

-- Title --
Zigzag Conversion — LeetCode 6 (Row-Bucket Simulation)

-- Description --
Zigzag Conversion (LeetCode 6) solved without computing a single coordinate.

The task: write a string in a zigzag pattern across numRows rows, then read it back line by line. It's tempting to work out the (row, column) of every character, but there's a much simpler model.

Keep one string bucket per row. Walk the input once and append each character to the current row's bucket. Track a direction: start at row 0 moving down, and flip the direction whenever you reach row 0 or the last row. That bounce is what traces the zigzag. When you're done, concatenate the buckets from the top row to the bottom.

Example: "PAYPALISHIRING" with 3 rows. Row 0 collects P, A, H, N; row 1 collects A, P, L, S, I, I, G; row 2 collects Y, I, R. Joined, that's "PAHNAPLSIIGYIR".

⏱️ O(n) time · O(n) space for the row buckets. You can drop to O(1) extra space by reading each row directly with index arithmetic: characters in row r appear at a fixed stride of 2·numRows−2, with an extra diagonal character for the middle rows.
