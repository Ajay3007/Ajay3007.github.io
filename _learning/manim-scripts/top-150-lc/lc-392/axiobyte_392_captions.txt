cell locks in with a mint glow); return i == s.size(). O(n) time (n=|t|),

-- Caption --
Is Subsequence — LeetCode 392 — greedy two pointers 👇

Is s a subsequence of t? That means: keep t's order, delete some of its letters, and end up with s.

The move: one pointer on each string. 👉
• scan t left→right with j
• whenever t[j] is the character s currently needs, tick it off and advance i
• always keep moving j
• if i ticks off ALL of s → true

s = "abc", t = "ahbgdc":
need 'a' → t[0]='a' ✓  (i→b)
'h' ≠ 'b' skip … 'b' ✓  (i→c)
'g','d' skip … 'c' ✓  → s fully matched → true ✅

Greedy works because taking the earliest possible match never hurts later ones.

→ O(n) time over t, O(1) space.

Bonus (cleaner code): one counter and a single range-for over t — same idea, tighter loop. (And if you have MANY s to test against one fixed t, preprocess t once and binary-search each character.)

-- Title --
Is Subsequence — LeetCode 392 (Two Pointers, O(1) Space)

-- Description --
Is Subsequence (LeetCode 392) solved with a greedy two-pointer scan.

s is a subsequence of t if you can delete zero or more characters from t, without reordering, and get s. Use one pointer i on s and another j on t. Sweep t from left to right; each time t[j] equals the character s currently needs (s[i]), advance i. Always advance j. If i reaches the end of s, every character of s was found in order, so s is a subsequence.

Example: s = "abc", t = "ahbgdc". i needs 'a' and t[0] is 'a' — match, i moves to 'b'. 'h' is not 'b', skip; 'b' matches, i moves to 'c'. 'g' and 'd' are skipped; 'c' matches, and i has now cleared all of s. Answer: true.

Why greedy is safe: matching the earliest available character in t can never make a later character harder to find, so there's no need to try other alignments.

⏱️ O(n) time where n is the length of t, O(1) extra space.

Bonus, cleaner code (shown as a flourish): a single counter and one range-based for loop over t — int i = 0; for (char c : t) if (i < s.size() && c == s[i]) i++; return i == s.size();

Follow-up: if you must answer many different s against the same t, preprocess t once — for example store, for each character, the sorted list of its positions and binary-search the next position — so each query is faster than a full scan.
