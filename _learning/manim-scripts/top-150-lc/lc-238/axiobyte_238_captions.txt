Product of Array Except Self — LeetCode 238 — no division allowed 👇

Return an array where answer[i] = the product of every element EXCEPT nums[i]. In O(n) time, and you can't use division (which would blow up on zeros anyway). 🚫➗

The intuition that cracks it:
answer[i] = (everything BEFORE i) × (everything AFTER i)

So you don't need the whole product — just the running product on each side. Two sweeps:

→ Pass 1 (left to right): fill ans[i] with the prefix product (everything before i)
← Pass 2 (right to left): multiply ans[i] by the suffix product (everything after i)

For [1,2,3,4,5,6]:
prefix pass → [1, 1, 2, 6, 24, 120]
suffix pass → [720, 360, 240, 180, 144, 120] ✅

And the second pass reuses the answer array with a single running variable → O(1) extra space. No division needed, so zeros just work. 🎯

-- Title --
Product of Array Except Self — LeetCode 238 (Prefix × Suffix, No Division)

-- Description --
Product of Array Except Self (LeetCode 238) — return an array where answer[i] is the product of every element except nums[i], in O(n) time and with no division.

The trick is to realize you don't need the total product at all. For any index, the answer is simply everything before it multiplied by everything after it. That splits the work into two running products — a prefix product from the left and a suffix product from the right.

Pass 1 goes left to right and fills each ans[i] with the product of everything before i (the running prefix). Pass 2 goes right to left and multiplies each ans[i] by the product of everything after i (the running suffix). Because the second pass reuses the output array and only needs one running variable, the extra space is O(1).

Example with [1,2,3,4,5,6]:
prefix pass -> [1, 1, 2, 6, 24, 120]
suffix pass -> [720, 360, 240, 180, 144, 120]

Avoiding division isn't just a constraint for fun — division would fail whenever the array contains a zero. The prefix/suffix approach handles zeros naturally.

⏱️ O(n) time · O(1) extra space (the output array doesn't count)
