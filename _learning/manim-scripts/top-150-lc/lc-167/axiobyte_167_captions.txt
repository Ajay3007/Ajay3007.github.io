── NOTE (template v3) ─────────────────────────────────────────
The canonical converging two-pointer on a SORTED array. l/r from both
ends; sum = a[l]+a[r]; sum<target -> l++ (need bigger), sum>target -> r--
(need smaller), sum==target -> return {l+1, r+1} (1-based). O(n) time,
O(1) space. NO Bonus card — the two-pointer is the optimal clean solution
and there's no slicker one-liner (a hash map would be O(n) space, binary
search O(n log n)); outro clears the walkthrough via clear_code(). Example
[1,3,4,5,7,11], target 9 -> [3,4], picked so it alternates r--/l++ before
matching. IMPORTANT: indices are 1-based per the problem statement.

Two Sum II — LeetCode 167 — the sorted-array trick 👇

Given a SORTED array, find the two numbers that add to target and return their (1-based) indices.

You could hash every number… but sorted hands you something better: a pointer at each end. 👉👈
• sum too small? the left number is the bottleneck → move l right for a bigger value
• sum too big? → move r left for a smaller value
• sum == target → done

[1,3,4,5,7,11], target 9:
1+11=12 > 9 → r--
1+7=8 < 9 → l++
3+7=10 > 9 → r--
3+5=8 < 9 → l++
4+5=9 ✓ → indices [3, 4]

Each step throws away a whole set of pairs that can't possibly work — that's why one pass suffices.

→ O(n) time, O(1) space. No hash map, no extra memory.

Two Sum II (Sorted) — LeetCode 167 (Two Pointers, O(1) Space)

-- Description --
Two Sum II - Input Array Is Sorted (LeetCode 167) solved with converging two pointers.

The array is sorted, and exactly one pair sums to the target; return their 1-based indices. Put one pointer l at the first element and another r at the last, and look at sum = numbers[l] + numbers[r]. If the sum is less than the target, the only way to increase it is to move l right to a larger value. If the sum is greater than the target, move r left to a smaller value. If the sum equals the target, return {l+1, r+1}.

Example: [1,3,4,5,7,11], target 9. 1+11=12 (>9, r--), 1+7=8 (<9, l++), 3+7=10 (>9, r--), 3+5=8 (<9, l++), 4+5=9 — match, so the answer is indices 3 and 4 (one-based).

Why it works: because the array is sorted, every move eliminates an entire group of pairs that cannot reach the target, so a single linear pass is enough — no need for the hash map you'd use on an unsorted Two Sum.

⏱️ O(n) time, O(1) extra space.
