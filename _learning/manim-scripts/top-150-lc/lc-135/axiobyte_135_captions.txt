── NOTE ───────────────────────────────────────────────────────
Two-pass greedy. The key insight: a single scan can only respect ONE
neighbor. So the left→right pass enforces "higher than my LEFT neighbor
⇒ more candy" (fixing up-slopes), and the right→left pass enforces the
same against the RIGHT neighbor (fixing down-slopes). Taking the max at
each index guarantees BOTH constraints hold at once — that's why the
peak in [2,3,4,3,2,1] jumps to 4 (max of its left-count 3 and its
right-count 4). This is O(n) time, O(n) space. An O(1)-space variant
exists (count consecutive up/down runs and add triangular numbers) —
same answer, trickier to read; the two-pass version is the interview
default.

-- Caption --
Candy — LeetCode 135 — the classic two-pass greedy 👇

Kids stand in a row, each with a rating. Hand out the FEWEST candies where (1) everyone gets at least 1, and (2) anyone with a higher rating than a neighbor gets more candy than that neighbor. Both neighbors. That "both" is the whole trap. 🍬

One scan can only look one way — so do two.
• Left → right: if r[i] > r[i-1], candy[i] = candy[i-1] + 1  (fixes every up-slope)
• Right → left: if r[i] > r[i+1], candy[i] = max(candy[i], candy[i+1] + 1)  (fixes every down-slope)

The max is the magic: it keeps whichever pass demanded more, so both rules hold at the same time.

For ratings = [2,3,4,3,2,1]:
left pass → [1,2,3,1,1,1]
right pass → [1,2,4,3,2,1]   ← the peak jumps to 4 because its right-hand drop is longer than its left-hand climb
sum = 13 candies ✅

→ O(n) time, O(n) space.

-- Title --
Candy — LeetCode 135 (Two-Pass Greedy)

-- Description --
Candy (LeetCode 135) solved with the classic two-pass greedy.

Children stand in a row, each with a rating. Distribute the minimum number of candies so that every child gets at least one, and any child with a higher rating than an adjacent neighbor gets strictly more candy than that neighbor. The subtlety is "adjacent neighbor" means BOTH sides, and a single left-to-right scan can only enforce one side.

The fix is two greedy passes. Left to right: whenever ratings[i] > ratings[i-1], set candy[i] = candy[i-1] + 1 — this makes every increasing run correct with respect to the left neighbor. Right to left: whenever ratings[i] > ratings[i+1], set candy[i] = max(candy[i], candy[i+1] + 1) — this fixes every decreasing run with respect to the right neighbor. Taking the max is what lets both constraints hold simultaneously: a peak ends up with the larger of "how far it climbed" and "how far it must descend."

Example: ratings = [2,3,4,3,2,1]. After the left pass the candies are [1,2,3,1,1,1]. After the right pass they become [1,2,4,3,2,1] — the peak at index 2 is bumped from 3 to 4 because its descending run on the right (needs 4) is longer than its ascending run on the left (needs 3). Summing gives 13, the minimum.

⏱️ O(n) time · O(n) space (an O(1)-space run-counting variant exists and gives the same answer)
