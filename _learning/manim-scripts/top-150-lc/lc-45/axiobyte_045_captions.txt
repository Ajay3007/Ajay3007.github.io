You can always reach the end — the question is the MINIMUM number of jumps. Brute force (try every jump + memoize) works but is O(n²). There's a clean O(n) greedy. 🧠

-- Title --
Jump Game II — LeetCode 45 (Greedy, O(n))

-- Description --
Jump Game II (LeetCode 45) solved with a greedy one-pass in O(n) time and O(1) space.

You're guaranteed to be able to reach the last index — the question is the minimum number of jumps. The greedy idea is to treat the array like BFS layers: farthest tracks how far the next jump could reach, and curEnd marks the boundary of the current jump's range. Scan left to right, always extending farthest with i + nums[i]. Each time i reaches curEnd, you've exhausted the current jump's reach, so you take another jump and push curEnd out to farthest. The number of times you do this is the answer.

Example: [2,3,1,1,4] → 0 → 1 → 4 = 2 jumps.

A brute-force recursion with memoization also works but runs in O(n²). A full recursion → memoization → greedy deep-dive is coming to the channel.
