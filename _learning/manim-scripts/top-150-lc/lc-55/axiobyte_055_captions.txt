-- Caption --
Jump Game — LeetCode 55 — greedy, O(1) space 👇

nums[i] tells you the max you can jump from index i. Can you get from the start to the last index?

The trick: don't simulate jumps. Just track ONE number — the farthest index you can currently reach. 🧠

Walk left to right. At each index i:
• if i is already beyond your reach → you're stuck, return false
• otherwise extend the reach: maxReach = max(maxReach, i + nums[i])
• if the reach hits the last index → return true

For [3,2,1,0,4]: your reach stalls at index 3 (the 0 is a dead end), so index 4 is unreachable → false. Change that 0 to a 1 and you'd make it ✅

→ O(n) time, O(1) space

-- Title --
Jump Game — LeetCode 55 (Greedy, O(1) Space)

-- Description --
Jump Game (LeetCode 55) solved with a greedy one-pass in O(1) space.

nums[i] is the maximum jump length from index i, and you start at index 0. Instead of simulating every possible jump, track a single number: the farthest index you can currently reach. Walk left to right — if the current index is already beyond your reach, you can never get here, so return false. Otherwise extend the reach with maxReach = max(maxReach, i + nums[i]). The moment the reach covers the last index, return true.

Example: [3,2,1,0,4] → the reach stalls at index 3 because the 0 there is a dead end and nothing before it reaches farther, so index 4 is unreachable → false. (Change that 0 to a 1 and it becomes true.)

Note: this is the standard "farthest index" formulation. A common alternative tracks the remaining reach (maxReach - i) instead — same algorithm, same O(n) time and O(1) space.

⏱️ O(n) time · O(1) space
